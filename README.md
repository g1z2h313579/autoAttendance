# 个人考勤

这台 Mac 的个人考勤工具：后台监听唤醒与睡眠事件，网页按首尾推算上下班时间，支持人工修改，并按公司 Excel 模板导出。数据只存在本机，不记录输入内容、窗口标题或屏幕画面。

## 使用

正式地址：<http://127.0.0.1:3939>。

1. 后台只在电源事件时记录，不需要打开项目、终端或网页。首次开盖／唤醒记上班，末次合盖／睡眠暂记下班，再次唤醒会更新；首尾之间的睡眠、锁屏、空闲都算连续工作。在月度记录中查看每天的类别和时间；点击日期查看时间线、网络和修改历史。
2. 修改类别、上班、下班或备注后点击“保存”。只改备注不会覆盖自动考勤。
3. 检查有标记的日期，处理地点未知、短工时和缺记录等情况，再点击“确认”。“确认无标记日期”只处理已结束的日期。
4. 点击“生成 Excel”。未确认记录会列出提示；确认了解后可以继续。跨零点和工作时间不完整必须先处理。
5. 下载后用 Excel 打开，公式会重算。空格预览不会重算合计。
6. 在表格下方的“邮件摘要”点击“复制邮件内容”，粘贴到邮件。类别和时间编辑会实时预览，工时按当前模板扣除休息时间，姓名、工作地点和每月交通费来自本机配置；导出前先保存表格修改。
7. 最终记录可锁定；解锁后才能修改或重新计算。导出时也可选择同时锁定。

设置页可管理公司网络、判定阈值、公司休息日、模板和额外导出目录。界面显示中文类别，写入 Excel 时使用模板规定的固定值。

切回网页、页面恢复或重新联网后会主动刷新记录；可见月页每分钟检查一次最新计算结果，不新增考勤采样。有未保存编辑时暂停刷新；已发出的刷新响应也会保留新输入的草稿。唤醒时网络尚未就绪会进行有限重试，取得网关后停止。

## 安装与升级

要求 macOS、Homebrew Node 22（至少 22.13）、npm 和 Xcode 命令行工具（用于构建原生电源监听器）。默认 Node 路径为 `/opt/homebrew/opt/node@22/bin/node`；其他位置使用 `NODE_BIN` 指定。

```bash
npm ci
cp .env.example .env.local
# 编辑 .env.local，填写自己的邮件信息
npm run deploy
```

部署会构建并安装采集程序和 Web 服务。两个服务由 launchd 管理，登录后启动、异常退出自动重启。升级代码后再次运行 `npm run deploy`；数据库迁移自动执行，数据不会删除。部署前请完成测试。

只升级采集程序：

```bash
npm run deploy:collector
```

程序必须放在 Application Support 下；launchd 访问桌面项目目录会受到 macOS 隐私限制。Web 只监听 127.0.0.1。

## 个人配置与共享仓库

姓名、工作地点和每月交通费分别通过 `.env.local` 中的 `KAOQIN_MAIL_NAME`、`KAOQIN_MAIL_WORKPLACE`、`KAOQIN_MAIL_TRANSPORT_YEN` 配置。交通费须为非负整数，单位为日元。未配置时显示待填写提示，交通费为零。修改后重启开发服务；正式环境重新执行 `npm run deploy`，部署脚本会单独安装权限为 600 的本机配置。

新安装没有预置公司网关。连接公司网络后，在设置页把出现的网络标记为公司。每位同事只维护自己这台 Mac 的配置与数据。

项目提供匿名、空白的 Excel 示例模板。首次使用前，请填写示例模板 V3 的姓名后在设置页上传，或上传布局兼容的个人模板；邮件姓名由本机配置单独指定。新上传模板存放在本机数据目录。升级会保留已有模板。

Git 只包含匿名默认模板和人工构造的测试样本。环境文件、个人 Excel 文件、数据库、日志、私有目录和本机验收文档均被忽略；`.env.example` 可提交供同事参考。个人模板应放到 `data/` 或 `private/`，不要覆盖仓库中的匿名示例文件。

## 开发与测试

```bash
npm run db:pull
npm run dev
```

开发地址：<http://127.0.0.1:3940>，数据库在 `data/dev/`。`db:pull` 会用 SQLite 在线备份覆盖开发库，正式库保持原样；覆盖前停止开发服务，避免旧连接仍访问先前数据。

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm run judge:month -- 2026-10
npm run tasks:check
```

月度判定脚本默认写开发库。任务检查脚本默认操作开发库，用控制台输出代替系统通知。开发服务与生产构建默认关闭定时任务，正式 launchd 服务会启用。

## 数据、备份和导出

- 数据目录：`~/Library/Application Support/kaoqin/`。
- 数据库：`kaoqin.db`；模板：`templates/`；导出：`exports/`；备份：`backups/`。
- 日志：`~/Library/Logs/kaoqin/`，主要查看 `collector.log` 和 `web.log`；进程崩溃输出在 `*.stderr.log`。
- Web 每十分钟检查：每日在线备份一次，保留最近三十份；每月第一次检查时生成上月草稿并通知；每年十二月提醒更新节假日数据。
- 草稿文件带“草稿”后缀，不会覆盖最终版。没有处理完的跨零点记录会使草稿任务失败，日志说明原因，下一次检查重试。
- SQLite 使用 WAL，不能仅复制 `kaoqin.db`；使用在线备份或 `.backup`。

恢复备份时先停止两个服务，保留当前数据库的在线备份，再用 SQLite 的 `.restore` 恢复选定文件，重新部署启动。不要在服务运行时直接替换数据库。

## 常见问题

**页面显示电源事件监听未运行**：没有新事件是正常情况，健康状态取决于监听进程。显示异常时查看：

```bash
launchctl print gui/$(id -u)/local.kaoqin.collector
```

**网页无法打开**：检查 `local.kaoqin.web` 服务和 `web.stderr.log`，确认 3939 端口没有被其他程序占用。

**误判到岗或居家**：设置页检查网关是否被标记为公司。公司换路由器后需要标注新网络；调整网络和规则会清除未锁定月份的确认状态。

**开会或睡眠**：首尾之间全部算连续工作，不再读取会议程序或空闲计时。首次开盖前或最终合盖后的工作需要人工调整。

**时间不准确**：上下班时间精确到分钟，不取整。业务日默认 05:00 分界。下班采用末次真实睡眠事件的暂定值，需要核对；没有结束事件时人工补齐。后台通知和维护唤醒会被过滤。

**节假日更新**：每年检查 `@holiday-jp/holiday_jp` 新版本并更新依赖、测试、重新部署；公司休息日在设置页维护。

**无法写额外导出目录**：检查绝对路径和 macOS 文件访问权限。默认导出始终保存在数据目录；无需设置额外目录。

## 卸载

```bash
npm run uninstall
```

停止两个常驻服务并删除部署程序，保留数据库、模板、导出、备份和日志。

## 已知限制

- 仅依据这一台 Mac；从家里远程操作公司里的这台电脑仍会被判成到岗。
- 公司模板不支持跨零点，必须人工处理后才能导出。
- 没有合盖／睡眠时无法推算最终下班，需要人工填写。
- 重启电脑后的自动启动需要实际重启验收；不为验证而强制重启电脑。

通用规格见 `doc/spec.md`。
