# 个人考勤系统 规格概要

> 共享版：仅保留通用规格，个人配置、真实数据和本机验收记录不进入仓库。

## 1. 背景与目标

每月需要向公司提交一份 Excel 考勤表（公司模板），过去是凭估算填写。

本系统要做到：

1. 自动记录这台 Mac 的唤醒与睡眠事件，推算每天的上下班时间、到岗还是居家、是否休假。
2. 随时在网页上查看和修改考勤记录。
3. 每月按公司模板原样导出考勤表。

## 2. 前提与范围

### 2.1 已确认的前提

| 项目 | 内容 |
|---|---|
| 判断依据 | 只依据这台 Mac。此电脑仅用于工作，没有其他工作设备 |
| 时间精度 | 写实际时间，精确到分钟（秒直接舍去），不做 10 分钟取整 |
| 到岗 / 居家 | 在公司网络上工作算 `出勤`，其他任何网络算 `在宅` |
| 加班、深夜 | 系统不计算，由模板公式自动算 |
| 使用者 | 单用户，仅本机访问，不需要登录 |

### 2.2 不做的事

- 多人、多设备、云同步
- 请假申请、审批流程
- 记录键盘内容、窗口标题、截屏（只记录电源事件及事件时的网络）

## 3. 术语

| 术语 | 含义 |
|---|---|
| 业务日 | 东京时间每天 05:00 到次日 05:00。凌晨加班算前一天 |
| 电源事件 | 首次开盖／用户唤醒、睡眠、屏幕变化等系统通知；不按分钟采样 |
| 暂定下班 | 末次真实睡眠的时刻；再次唤醒会延长，需要人工核对 |
| 连续工作区间 | 首次开盖／唤醒到末次睡眠，中间睡眠、锁屏和空闲均计入 |
| 公司网络 | 已登记为公司的路由器（默认网关）MAC 地址 |
| 补齐 | 用系统电源日志恢复监听器停机期间遗漏的事件 |
| 考勤类别 | 模板 E 列的值，只能是下面 6 个固定值之一 |

考勤类别的固定值（模板下拉框的选项，必须原样写入）：

`出勤`（到岗）、`在宅`（居家）、`有給休暇`（带薪休假）、`欠勤`（缺勤）、`代休`（调休）、`休日出勤`（休息日上班）

## 4. 系统构成

```
┌──────────────────────────┐          ┌────────────────────────────────┐
│ 采集程序（常驻）          │  写入    │ SQLite 数据库                  │
│ - 监听唤醒与睡眠事件        ├────────▶│ ~/Library/Application Support/ │
│ - 每小时导入电源日志      │          │   kaoqin/kaoqin.db             │
└──────────────────────────┘          └───────────────┬────────────────┘
                                                      │ 读写
                                      ┌───────────────▼────────────────┐
                                      │ Web 服务（常驻，Next.js）       │
                                      │ http://127.0.0.1:3939          │
                                      │ 判定、界面、导出、定时任务      │
                                      └────────────────────────────────┘
```

- Node 采集服务和 Web 服务由 launchd 管理，登录后自动启动，异常退出自动重启；采集服务启动一个原生 Swift 电源监听子进程。
- **采集程序只记录事实，不做任何判断。** 判断全部在 Web 服务里完成。这样以后修改判定规则，可以对过去的数据重新计算。
- 程序和数据都放在 `~/Library/Application Support/kaoqin/`，不放在桌面。桌面目录受 macOS 隐私保护，后台进程访问会被拒绝。

## 5. 数据采集

### 5.1 电源事件监听

- 原生 Swift 程序通过 `NSWorkspace.shared.notificationCenter` 接收唤醒、即将睡眠、亮屏、灭屏和关机通知；输出带 Unix 秒的消息，由 Node 服务立即存入 `power_events`。
- 不再按分钟读取 HID 空闲计时、锁屏状态或阻止熄屏的程序，不记录键鼠和窗口。
- 启动及唤醒／亮屏事件时读取一次网络，沿用 `samples` 表保存网络快照；新快照的空闲秒数等活动字段为 NULL，不用于推测操作时间。
- 子进程未就绪或退出时显示异常；子进程失效后 Node 退出，由 launchd 重启。健康检查查看两个进程状态，不要求近期出现电源事件。
- 睡眠中的事件可能由下一次唤醒时的系统日志补齐，睡眠区间本身不从工作时长中扣除。

### 5.2 电源日志导入

- 启动、唤醒后及每小时一次，解析 `pmset -g log`，把亮屏、灭屏、睡眠（含原因）、唤醒事件存进数据库，重复的自动去掉；系统日志可补充原生通知没有提供的准确唤醒原因。
- 系统日志按大小滚动，实测只保留约 4 天的亮屏记录，所以必须定期导入，不能等用的时候再读。
- 用途：恢复首次安装之前、服务停机或睡眠前没有及时写入的电源事件。
- 已超出系统日志保留范围的记录需人工补录；个人日志快照只保存在被忽略的数据目录。

### 5.3 公司网络识别

- **不用 Wi-Fi 名称。** macOS 对普通程序屏蔽 SSID，读出来是 `<redacted>`。
- **用默认网关的 MAC 地址识别。** 新安装不预置公司网络；使用者在设置页标记自己的公司网关。
- **不能只看网关 IP。** 家庭和公司的私有网段 是常见的路由器默认网段，家里很可能也一样。
- **网关 MAC 从系统网络配置读取，不用 `arp`。** macOS 的"本地网络"隐私限制会让未授权的进程（包括 launchd 启动的 node）看到空的 ARP 表，实测 `arp -n` 返回"no entry"。系统网络服务（configd）在每个网络服务的 IPv4 状态里记录了路由器 MAC（`ARPResolvedHardwareAddress`，以及 `NetworkSignature` 里的 `IPv4.RouterHardwareAddress`），用 `scutil` 读取不需要授权。
- 系统会记住所有见过的网关。设置页里可以把任意一个标记为公司，用于公司换路由器或有多个网关的情况。工作日遇到没见过的网关时，界面上会提示。
- 开着 VPN 时，主网络服务是 VPN，没有路由器 MAC。这时改用有路由器 MAC 的物理网卡服务。

## 6. 判定规则

用户于 2026-10-09 选择自动推算首尾，替代原来的每分钟活跃采样规则。

### 6.1 上下班首尾

1. 业务日默认为东京时间 05:00 到次日 05:00，未来日期不计算。
2. 当天第一次有依据的开盖／用户唤醒或亮屏作为上班，末次真实睡眠或关机作为暂定下班。
3. 再次唤醒后继续延长，首尾之间的睡眠、锁屏、空闲和会议连续计入一个区间，不按键鼠活跃度扣时。
4. 正在使用的当天暂统计到当前时刻；睡眠后暂显示该次睡眠时间。已结束业务日缺少最后睡眠时，下班留空并提示“缺少结束事件”，不补到凌晨。
5. DarkWake、通知唤醒和后台维护睡眠不当作工作。有明确用户唤醒依据的短暂使用保留；没有用户唤醒依据且短于两分钟的亮屏视为噪声。
6. 没有电源起始依据时，旧版本有效采样仍可恢复历史首尾，中间空白同样算连续区间。新网络快照不会制造上班记录。
7. 自动时间带“下班待核对”；人工覆盖优先，已锁定月份不重算。

### 6.2 时长与输出

- 页面“在岗”与“区间 / 分钟”表示上下班之间的连续时长。
- 底层兼容字段 `active_min` 在新判定中保存连续区间分钟；不再累计活跃会话。`office_min` 保留兼容，不用于新判定或页面展示。
- Excel 仍写入实际起止分钟，由公司模板扣除固定休息并计算加班；邮件工时使用相同模板规则。中间睡眠不会额外扣除。
- 下班跨过零点仍带“跨零点”标记，模板不支持，需人工处理。

### 6.3 考勤类别

| 情况 | 考勤类别 | 标记 |
|---|---|---|
| 工作区间出现公司网络快照 | `出勤` | 下班待核对 |
| 工作区间只出现已知其他网络 | `在宅` | 下班待核对；未命名网络另提示新网络 |
| 有工作区间但没有可用网络 | 空（待选） | 地点未知、下班待核对 |
| 已结束工作日没有开始依据 | `有給休暇` | 休假待确认，可改为欠勤或调休 |
| 休息日连续区间至少 60 分钟 | `休日出勤` | 休息日上班待确认、下班待核对 |
| 休息日不足阈值 | 空，时间留空 | — |

公司网络通过默认网关 MAC 判断，不要求累计公司分钟。业务日分界、休息日区间阈值、短工时阈值在设置页修改。旧采样相关设置仅为历史恢复保留，不再展示。

### 6.4 休息日

- 周六、周日、日本法定节假日，以及设置中的公司休息日。
- 日本节假日使用 `@holiday-jp/holiday_jp`，每年更新依赖。

### 6.5 标记

| 标记 | 处理 |
|---|---|
| 下班待核对 | 检查暂定下班，必要时人工修改再确认 |
| 缺少结束事件 | 补齐下班；没有合盖／睡眠时无法自动确定最终结束 |
| 地点未知 | 指定到岗或居家 |
| 休假待确认 | 核实休假、缺勤或调休 |
| 休息日上班待确认 | 核实是否上班 |
| 工时过短 | 默认首尾少于四小时，检查起止 |
| 跨零点 | 模板不支持，必须处理 |
| 新网络 | 在设置中命名，并按实际情况标记公司 |

## 7. 人工修改与确认

- 每天保存两套值：自动判定值（随时可以重算）和人工修改值。
- 只要人工修改过，这一天的类别、上班、下班三项就以人工值为准。点"恢复自动"会删除人工值。
- 每次修改都记入修改历史（字段、旧值、新值、时间）。
- 每天有"已确认"状态。批量确认只处理已结束、无标记的日期；当天和未来不能确认。自动结果改变会撤销自动日期的确认；修改网络或规则会撤销未锁定月份的确认。
- 月份可以锁定。锁定后不再重算，也不能修改，需要时可以解锁。导出时可以顺便锁定。
- 只改备注不创建人工考勤覆盖；修改备注会撤销确认。锁定月份的备注也不能修改。

## 8. 界面

### 8.1 月度视图（首页）

- 每天一行：日期、星期、考勤类别、上班、下班、在岗时长（下班减上班）、连续区间分钟、来源（采集／补录／人工）、标记、备注、确认状态。
- 类别、上班、下班、备注可以直接在表格里修改。
- 顶部显示：各类别天数、未处理的标记数、采集程序状态（超过 5 分钟没有新采样时显示红色警告）。
- 操作：切换月份、一键确认、复制邮件摘要、导出 Excel、锁定月份。
- 表格下方、导出区域上方显示邮件摘要：姓名、工作地点和每月交通费从被忽略的 `.env.local` 读取。邮件正文保留通用模板格式，说明与按钮使用中文。
- 邮件摘要按页面中当前类别、上下班时间实时计算，包含未保存编辑；保存和恢复自动后跟随记录更新，切换月份后清除旧月预览。导出 Excel 前需要保存修改。
- 工作日合计为出勤、在宅及休日出勤；出勤和在宅分别按固定类别统计，休暇为有給休暇与代休之和；未来日期不参与，进行中的日期使用当前已知时间。
- 邮件工时与默认公司模板 U、X、AA 列口径一致，从当前模板规则区读取时间并扣除午休及晚间休息，保留分钟（如 7H52M）。缺少时间的记录暂不计工时并提示；跨零点或无法读取规则时不提供有效工时，禁用复制。
- 点开某一天会显示详情：
  - 时间线：05:00 到次日 05:00 的横条，公司网络、其他到岗、居家和地点待核实用不同颜色表示
  - 判定依据（会话列表、所在网络）
  - 修改历史

### 8.2 设置页

- 网络：见过的网关列表（MAC、最近 IP、首次和最近出现时间），可以标记为公司、加备注名。
- 业务日分界、休息日区间阈值、短工时阈值、公司休息日。
- 模板：查看当前模板，上传新模板。
- 导出目录（可选）、采集程序状态。

## 9. 导出

### 9.1 模板结构

以下为兼容的匿名示例模板布局：

| 单元格 | 内容 | 由谁填 |
|---|---|---|
| O1、R1 | 年、月 | 系统 |
| E13:E43 | 每天的考勤类别（下拉框） | 系统 |
| I13:I43 | 上班时间 | 系统 |
| L13:L43 | 下班时间 | 系统 |
| 其他所有单元格 | 日期、星期、工时、提前上班与加班时间、深夜时间、各项合计 | 模板公式自动算 |

- 第 13 行是 1 号，第 43 行是 31 号。不足 31 天的月份，模板公式会自动显示 `--`。
- 午休 12:00–13:00 由公式自动扣除（晚上加班时还会扣 19:00–19:30 和 21:30–22:00），系统不需要识别午休。
- 右侧规则区写有"开始时间向上取整、结束时间向下取整到 10 分钟"，但公式实际没有用到。按已确认的前提，直接写实际时间。
- 合计里的"出勤（日）"只统计 `出勤`，不包括 `在宅`。这是模板本身的公式，不修改。
- 周末和节假日的 E 列留空（9/21–9/23 的连休也是空的）。

### 9.2 写入方式

- 不把整个 Excel 读进来再写出去，而是直接修改 xlsx 内部 XML 里上面那几类单元格。样式、公式、下拉框、条件格式（周末变色）、打印区域都原样保留。
- 时间写成 Excel 的时间数值（分钟 ÷ 1440），沿用原单元格的样式。
- 清除所有公式单元格里缓存的旧计算结果，并设置"打开时完全重算"。这样用 Excel 打开时合计一定是新的。注意：Mac 按空格键预览不会重算，看不到合计。
- 文件名：`勤務表_<姓名>_<YYYYMM>.xlsx`，姓名取自模板 V3 单元格。

### 9.3 导出前检查

- 有未确认的天或未处理的标记时，列出来提示，可以选择"仍然导出"。
- 有"跨零点"的天时不允许导出，必须先处理。
- 工作类别缺少上班或下班时间也不能强制导出。未来日期不参与检查；进行中的日期会提示。
- `POST /api/export/[ym]` 生成文件并可锁定；`GET` 只下载已生成文件，不改变数据库。写接口核对本机 Host 和来源。

### 9.4 更换模板

在设置页上传新模板时，系统先检查布局：

- O1、R1 是数字
- E10 是考勤类别表头
- I11、L11 是上下班表头
- A13 是日期公式

检查不通过就拒绝上传，并说明原因。

### 9.5 每月自动生成

服务启动五秒后及每十分钟检查一次：每月首次检查生成上个月草稿，保存到 `exports/`，发系统通知；离线错过一号时，下次启动补做。草稿带 `_草稿` 后缀，不覆盖最终版。已有最终版的月份跳过。失败会重试；数据库租约防止多个实例重复执行。通知脚本执行成功不代表用户一定看见通知，仍受 macOS 通知设置影响。

## 10. 数据模型概要

| 表 | 内容 | 写入方 |
|---|---|---|
| `samples` | 事件网络快照及历史分钟采样 | 采集程序（同秒快照合并；唤醒取不到网关时有限重试） |
| `power_events` | 电源日志事件 | 采集程序（去重追加） |
| `networks` | 见过的网关及是否为公司 | 采集程序登记，Web 标记 |
| `day_auto` | 每天的自动判定结果（可重算的缓存） | Web |
| `day_manual` | 每天的人工修改值 | Web |
| `day_meta` | 备注、确认时间 | Web |
| `edit_logs` | 修改历史 | Web |
| `months` | 月份锁定、导出记录 | Web |
| `templates` | 模板文件记录 | Web |
| `settings` | 阈值等配置（JSON） | Web |

表结构与初始化逻辑见 `src/lib/db/migrations.ts`。

## 11. 非功能要求

| 项目 | 要求 |
|---|---|
| 资源占用 | 原生监听器等待电源通知，仅启动／唤醒时记录网络；每小时补齐电源日志，无每分钟采样 |
| 可靠性 | launchd 自动重启；SQLite 使用 WAL 模式；每天用 Node SQLite 在线备份一次，保留 30 份 |
| 安全与隐私 | Web 只监听 127.0.0.1；不记录输入内容、窗口、截屏；数据只存在本机 |
| 时间 | 内部一律存 Unix 秒，计算一律按 Asia/Tokyo |
| 语言 | 代码注释、文档、界面、提交信息全部用中文（模板固定值除外） |

## 12. 已知限制

- 首次开盖之前或末次合盖之后的工作无法自动确定，需要人工修改起止；区间中间的会议和睡眠计入工作。
- 没有合盖／睡眠时缺少最终结束事件，需要人工填写下班。
- 如果从家里用远程软件操作放在公司的这台 Mac，会被判成 `出勤`。
- 跨零点下班不支持（模板的限制）。
- 节假日数据依赖 npm 包，每年要更新。
- 10/1–10/2 超出了日志范围，需要手动录入。

## 13. 决策记录

| 日期 | 决策 | 理由 |
|---|---|---|
| 2026-10-08 | Next.js 全栈 + SQLite | 用户指定；单机使用，越简单越好 |
